# 2026-09-12 学习记录

## 浮点类型 float / double

- 小数默认是 `double`，要存进 `float` 必须在末尾加 `F`（和 `long` 要加 `L` 是同一个道理）
- 原因：`double` 不能隐式转成 `float`（属于"大范围 → 小范围"）
- 位数：`float` 4 字节（1 符号 + 8 指数 + 23 尾数），`double` 8 字节（1 符号 + 11 指数 + 52 尾数）
- **决定精度的是尾数位数**：`float` 约 7 位有效数字，`double` 约 15~16 位

```java
float  a = 9.99F, b = 0.01F;   // 不加 F 直接编译报错
double d = 1.33;               // 小数默认就是 double

System.out.println(1.0F / 3.0F);   // 0.33333334        ← 只有 7 位
System.out.println(1.0  / 3.0);    // 0.3333333333333333 ← 15 位以上
```

## 浮点数不精确的原因

小数转二进制靠"乘 2 取整"，有些数能整除、有些会**无限循环**：

```
0.25：0.25×2=0.5→0   0.5×2=1.0→1   结束        ✅ 能精确表示
0.1 ：0.1×2=0.2→0  0.2×2=0.4→0  0.4×2=0.8→0
      0.8×2=1.6→1  0.6×2=1.2→1  0.2×2=0.4→0  ← 循环回来了，永远除不尽  ❌
```

所以 `0.1` 只能存近似值，误差在参与运算后会被放大：

```java
System.out.println(0.1 + 0.2);          // 0.30000000000000004
System.out.println(0.1 + 0.2 == 0.3);   // false
```

**结论**：浮点数不能用于需要精确结果的计算（金额要用 `BigDecimal`），比较时不能直接用 `==`。

## long 转 float 会丢精度

`long`（64 位）转 `float`（32 位）是被允许的隐式转换，因为 `float` 靠科学计数法的指数位能表示很大范围。但 **`long` 有 64 位、`float` 尾数只有 23 位**，超出部分的低位直接丢失：

```java
long L = 9007199254740993L;
System.out.println((float) L);    // 9.007199E15  ← 末尾的 93 没了
System.out.println((double) L);   // 9.007199254740992E15
```

**范围够 ≠ 精度够**，这是位数和精度两个不同的概念。

## char 字符类型

- `char` 是 **16 位无符号整数**，范围 0 ~ 65535，专门用来存一个字符
- 单引号只能放**一个**字符，双引号才是字符串 `String`

```java
char a = 65;          // 直接写码点，输出 A
a = '?';              // 单引号包一个字符
a = '\n';             // 转义字符：换行
a = '\'';             // 转义字符：单引号本身（要加反斜杠）

String b = "hello world";   // String 是引用类型，双引号，长度任意
```

- 常用码点：`'0'`=48、`'A'`=65、`'a'`=97
- `char` 参与运算时会提升为 `int`，所以 `char c = 'A' + 1;` 得到 `'B'`
- 转义字符用反斜杠：`\n` 换行、`\t` 制表、`\'` 单引号、`\\` 反斜杠、`\uXXXX` 码点

## byte 和 char 之间不能互转

这两个类型**双向都禁止隐式转换**，各有各的原因：

| 赋值 | 方向 | 被拦的原因 |
|---|---|---|
| `b = a;`（byte → char） | 有符号 → 无符号 | `a` 可能是负数，`char` 装不下 |
| `a = b;`（char → byte） | 大范围 → 小范围 | `char` 最大 65535，超出 `byte` 的 127 |

```
byte:  -128 ────── 0 ────── 127
char:     0 ────────────── 65535
```

只能强制转换，后果自负：`char x = (char) a;`、`byte y = (byte) b;`

## 二元数值提升

`byte`、`short`、`char` 参与 `+ - * / %` 运算前，**先一律升成 `int`**：

```java
byte a = 10, b = 3;
// byte c = a + b;   // ❌ 编译失败：a+b 的结果是 int
int c = a + b;       // ✅ 13
```

例外：**`+=` 这类复合运算符编译器会自动强转**，所以不报错——但溢出时也不会有任何提示：

```java
byte d = 127;
d += 1;              // 不报错，d 悄悄变成 -128
```

## 运算类型看操作数，不看左边的变量

```java
int a1 = 5, b1 = 10;
int c1 = a1 / b1;      // 0     int ÷ int 还是 int
float c2 = a1 / b1;    // 0.0   先算成 int 0，再变 0.0，小数已经没了

float c3 = a1 / (float) b1;   // 0.5  先改变类型，除法才是浮点除法
```

**左边变量的类型决定"能不能存下"，操作数的类型决定"算出来是什么"。** 顺序不能反。

## 整数除法的截断方向

Java 的 `/` 是**向 0 截断**，不是向下取整，负数会踩坑：

```java
 5 / 2   →  2
-5 / 2   → -2      （Python 的 // 是 -3，向下取整）
-5 % 2   → -1      （Python 的 % 是 1）
```

要 Python 那种行为得用 `Math.floorDiv` / `Math.floorMod`：

```java
Math.floorDiv(-5, 2)   // -3
Math.floorMod(-5, 2)   //  1
```

## 字符串拼接

`+` 遇到 `String` 就变成拼接，**从左往右算**，所以结果取决于顺序：

```java
byte a = 10;
a + 1.5 + "hi"    →  11.5hi     （先算 10+1.5=11.5，再拼字符串）
"hi" + a + 1.5    →  hi101.5    （先拼成 hi10，再拼 1.5）
```

## 四种取整

| 方法 | 规则 | 2.5 | -2.5 | 返回类型 |
|---|---|---|---|---|
| `(int) x` | 砍掉小数（向 0 靠） | 2 | -2 | int |
| `Math.floor(x)` | 向下取整（向 −∞） | 2.0 | -3.0 | double |
| `Math.ceil(x)` | 向上取整（向 +∞） | 3.0 | -2.0 | double |
| `Math.round(x)` | 四舍五入（.5 向上） | 3 | -2 | **long** |

- `(int) 2.9` 得 2，**不是**四舍五入
- `Math.round` 返回的是 `long`，要存 int 得自己转
