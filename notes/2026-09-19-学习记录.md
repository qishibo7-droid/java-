## Floyd-Warshall 全源最短路

状态表每格存两样东西：`D[i][j] = [最短距离, 完整路径]`

```python
for k in range(NODES):
    for i in range(NODES):
        for j in range(NODES):
            d1, p1 = D[i][k]
            if d1 == INF:
                continue
            d2, p2 = D[k][j]
            if d1 + d2 < D[i][j][0]:
                D[i][j] = [d1 + d2, p1 + p2[1:]]
```

- 三层循环 `k → i → j`，把 `k` 当中转站挨个试
- 路径拼接 `p1 + p2[1:]`，`[1:]` 是**去掉重复的中转点 k**（`p1` 结尾和 `p2` 开头都是 k）
- 复杂度 O(n³)，10 个节点就 1000 次比较
- 每格同时存距离和路径，后面用的时候不用再回溯

## 元组配对技巧

```python
zip((begin,) + o, o + (v,))
# (begin,) + o  →  (0, 5, 6, 8)
# o + (v,)      →  (5, 6, 8, 4)
# 配对结果：(0,5) (5,6) (6,8) (8,4)
```

- `(begin,)` 是**单元素元组**，`+` 是元组拼接，不是加法
- 拼出"起点 + 中间顺序 + 终点"后，不用写一堆下标就能一段段查表

## 全排列暴力搜索

- 固定终点，把其余待送点全排列，取总路程最短的顺序：`min(itertools.permutations(others), key=...)`
- 再让每个点都当一次终点，取全局最快 → 本次第一阶段 63 分钟（终点 4）
- 代价是阶乘：n 个点 n! 种顺序，节点一多就跑不动，得换贪心或启发式
- Java 里**没有现成的全排列**，要自己写回溯

## 两阶段配送

- 优先件先单独求最快（业务约束：优先件必须最快），再接着送普通件
- **"停靠顺序"和"实际经过"不是一回事**：停靠 `[0, 5, 6, 8, 4]`，实际走了 `[0, 3, 5, 3, 6, 8, 3, 0, 4]`，中间点是最短路穿过去的
- 路上经过的普通件可以顺路送掉（本次顺路送了节点 3）
- 本次结果：第一阶段 63 分钟 + 第二阶段 37 分钟 = 总耗时 100 分钟
