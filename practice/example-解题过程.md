# example 解题过程总结

对应代码：`practice/example.java`
涉及知识点：强制类型转换、整数的二进制表示、IEEE 754 浮点数编码、浮点数的相等比较

## 一、这道题在做什么

1. `float b = 27.32F; a = (int) b;` 把浮点数塞进 int，看丢了什么
2. 手工把 `27.32` 编码成 float 的 32 位（IEEE 754），再用代码验证

## 二、通用过程：任意十进制小数 → float 的 32 位编码

| 步骤 | 做什么 | 27.32 的例子 |
|---|---|---|
| 1 | 整数部分转二进制：除 2 取余，**倒着读** | 27 → 11011 |
| 2 | 小数部分转二进制：乘 2 取整，**正着读** | 0.32 → 01010001111010111000… |
| 3 | 规格化：小数点左移，写成 `1.M × 2^E` | 1.10110101000111101011100… × 2^4 |
| 4 | 阶码字段 = `E + 127` | 4 + 127 = 131 = 10000011 |
| 5 | 尾数取 23 位（`1.` 后面那串），多的截断 | 10110101000111101011100 |
| 6 | 按 `S(1) \| E(8) \| M(23)` 拼接，再转 16 进制 | 0100 0001 1101 1010 1000 1111 0101 1100 → 0x41DA8F5C |

速算技巧：**E = 整数部分二进制的位数 - 1**（11011 有 5 位 → E = 4）。

## 三、判断"能不能精确表示"

- 小数部分的二进制要有限，**分母必须只含因子 2**：0.5、0.25、5.25（= 101.01）都能精确
- 分母含因子 5 就必然循环：0.32 = 8/25 → 无限循环 → 一定失真
- 所以 `27.32F` 实际存的是 `27.31999969482421875`

## 四、代码验证（复习时直接跑这段）

```java
float f = 27.32F;
System.out.printf("%08X%n", Float.floatToIntBits(f));   // 41DA8F5C，和手算对上
int i = (int) f;                                        // 27，小数被砍掉
System.out.println(Integer.toBinaryString(i));           // 11011
```

实测结果（JDK 24）：

```
bits(27.32F) hex = 41DA8F5C
bits(5.25F)  hex = 40A80000
exact value      = 27.31999969482421875
(int) 27.32F     = 27        向零截断，不是四舍五入
(int) -27.32F    = -27       负数也是向零截断
```

## 五、这类题带出的通用结论

1. **类型转换**：大范围转小范围必须写 `(目标类型)`；浮点转整数**直接丢小数**，要四舍五入得用 `Math.round`
2. **浮点编码**：十进制小数转 float/double 就是上面 6 步，套公式即可，双精度只要把 127 换成 1023、尾数取 52 位
3. **浮点比较**：不要用 `==`

```java
0.1 + 0.2 == 0.3        // false（double）
0.1F + 0.2F == 0.3F     // true（float 这次刚好凑上，属于运气，不能当规律）
Math.abs(a - b) < 1e-6  // 正确写法：用误差范围比较
```

第 3 条是这道题最值钱的地方：同一个式子换 double 结果就反了，所以**浮点数的相等判断一律用误差范围**。

## 六、解题的固定套路（下次遇到同类题照着走）

1. 先想清楚**要什么进、什么出**：十进制 → 二进制？二进制 → 十六进制？
2. 整数和小数**分开处理**（除 2 取余 / 乘 2 取整）
3. 编码类题目套固定的几步：转二进制 → 规格化 → 算阶码 → 取尾数 → 拼接 → 转进制
4. 写完**用代码验算**，别信手算：`Float.floatToIntBits` / `Integer.toBinaryString` / `Integer.parseInt(s, 2)`
5. 手算和实测不一致时，先怀疑自己哪一步抄错位，逐位对齐比整段重算快
